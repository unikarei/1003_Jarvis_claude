## 5. 実機で確かめたこと（Mac mini、2026-11-14）

- Claude Code 2.1.296 を本番と同じ引数（`--restricted --strict-mcp-config --mcp-config --tools "WebSearch,WebFetch" --allowedTools … --permission-mode dontAsk --disable-slash-commands`）で起動: 使える道具は `WebFetch`・`WebSearch` と Jarvis の 4 つだけ。`jarvis_status` が答え、Bash・Write・Task（別のエージェント）は道具がなく実行されず、作業フォルダにファイルは作られなかった。許可していない Jarvis の道具（`memory_note` を外した試験）は断られた。
- 本物の `orchestrator.handle` で: 「覚えておいて」→ `memory_note` で記憶のメモに書いた（「Owner の好きな花はリンドウ。」）、状態の質問 → `jarvis_status`、「Bash で ls を実行して」→「この会話では、コマンドの実行やファイルの一覧を見ることはできません。」、4 発言とも同じプロセス。作業フォルダには `mcp.json` と `stderr.log` だけ。
- Codex CLI 0.169.0-alpha.11.1 の app-server: MCP の道具と Web 検索はコードの実行（`functions.exec`）を通してしか呼べず、`code_mode_host` を無効にしたままでは使えなかった（「道具が見つかりません」）。Codex は答えるだけのまま（spec §3.4.12 I）。同じ会話のスレッドに 2 発言目を送り、文脈が続くことを確かめた。
- 見つかった課題: Codex のモデルには、機能 `multi_agent` を無効にしても別のエージェントの道具（`collaboration.spawn_agent` など）が見えていて、呼ぼうとした（スレッドを保存しない設定のため Codex の中で失敗し、app-server の項目としては届かなかった）。今の本番にも当てはまる。

## 6. 評価の限界と次の判断

- 評価セットは架空で短い。switch は強制の失敗（上限の知らせ）で、本物の上限・落ちたプロセスからの切り替えは単体テスト（偽のプロセス）で確かめた。
- 声の会話（割り込み・読み上げ）とブラウザの会話は、実機では測っていない（Owner の確認の手順は PR に書く）。
- Claude の会話の評価は dev の 30 会話だけ（縮小版）。
- 提案: 会話の評価の cannot_do のうち Web 検索を頼む発言の期待を、「Web 検索が使えるときは調べて短く答え、出典を示す」に改める（別の作業、Owner の確認の後）。
