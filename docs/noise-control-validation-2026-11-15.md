# ブラウザ音声の雑音対策（T-2801）

Owner 事前承認（上位 AGENTS.md §2.1）。仕様の正本はワークスペース spec §3.4.9、ADR-0041、testing §23。先に仕様を記録して実装した。

音量判定では再生を仮停止し、AudioBuffer・再生位置・待ちの文を保持する。既存の faster-whisper に同梱された Silero で、1秒以内の録音をローカルで確認する。発話確認と既存の最小発話長の両方を満たしてから、従来の interrupt を1回送る。雑音・失敗・1.5秒の時間切れでは続きから再生し、LLMやスキルを再実行しない。ブラウザに noiseSuppression を要求し、再生・発話中を除いて背景音のしきい値を緩やかに更新する。

並行して main に入った T-2503（1003 #92、504f7b7）を統合した。承認カードが既に出ている間はマイクを受け付けない。候補の途中でカードが来た場合も、確認中はボタンを実行できず、復帰で期限を延ばさない。

検証:

- Node の実際の app.js を使う8件: 150msの物音、同じ文の0.7秒位置からの再開、startの二重送信なし、発話確定時のinterrupt/utterance各1回、古い結果の破棄、エラー/時間切れで再開、確認中の承認保留と期限。
- 全pytest 1,651件成功（140.38秒、既存のGoogle試験の戻り値と予備索引の警告4件）。承認カード到着時の競合修正後は、ブラウザ会話の関連79件を再実行し成功（17.26秒）。追加行の秘密情報0件。
- Python: 既存HTTP認証（Cookie・Origin・CSRF）、短いWAVの長さと同時実行制限、判定前後の発言照合、失敗時に秘密のエラー本文を返さないこと。判定APIはsubmit・interrupt・LLM・DB・ツールを呼ばない。
- 実際のSileroで無音・一定音・固定乱数のホワイトノイズ・600Hzの正弦波を発話なしと判定。
- macOS内蔵Kyokoで検証文を一時ファイルに合成（スピーカー再生なし）。1秒窓・0.25秒刻みの17区間すべてを発話ありと判定。録音・合成ファイルはGitに入れていない。
- Windowsの実マイク・実際の部屋の物音・小声・テレビの人声・停止まで300msの実測は未実施。背景の人声とOwnerの識別は行わない。MacのCLI経路は対象外。

本番は未反映。Codexの権限はPRまで（AGENTS.md §8.1）。Claudeのレビュー・マージ後、voice.webのサーバーを再起動し、Windowsのページを再読み込みしてT-2802を確認する。戻す場合は雑音対策PRをrevertし、同じく再起動・再読み込みする。
